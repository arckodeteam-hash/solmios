📋 Cómo Usar los Templates de PR

Guía paso a paso + Cómo usar IA para llenarlos

🔄 Flujo Básico de Uso

1. Identificar el tipo de trabajo
↓
2. Seleccionar el template correcto
↓
3. Llenar el template (manual o con IA)
↓
4. Crear PR en GitHub/GitLab
↓
5. Esperar revisión de QA-DEV

📝 Paso a Paso para Llenar el Template

PASO 1
Crear la rama correcta
Antes de empezar, crea la rama con el nombre correcto:
# Para Feature:
git checkout pre-produccion && git pull
git checkout -b feature/nombre-tarea

# Para Fix:
git checkout pre-produccion && git pull
git checkout -b fix/nombre-fix

# Para Refactor:
git checkout pre-produccion && git pull
git checkout -b refactor/nombre-modulo

# Para Hotfix:
git checkout main && git pull
git checkout -b hotfix/nombre-hotfix
PASO 2
Seleccionar el template
Elige el template según tu trabajo:
⭐ Versión Simple:
  • FEATURE_SIMPLE.md
  • REFACTOR_SIMPLE.md
  • BUG_FIX_SIMPLE.md

Para trabajos directos y sencillos

⭐⭐⭐ Versión Detallada:
  • FEATURE.md
  • REFACTOR.md
  • BUG_FIX.md

Para trabajos complejos con muchos cambios

PASO 3
Llenar el template
Tienes 3 opciones:
✍️
Opción 1: Manual

Escribir cada campo tú mismo

🤖
Opción 2: Con IA (Recomendado)

Usar ChatGPT/Claude para ayudarte

⚡
Opción 3: Script

Script que genera el template

PASO 4
Crear el Pull Request
Sube tu código y crea el PR en GitHub/GitLab:
git add .
git commit -m "feat: descripción del cambio"
git push origin feature/nombre-tarea

# Luego ir a GitHub/GitLab y crear PR
# Seleccionar el template correspondiente
# Llenar los campos
PASO 5
Esperar revisión
Joel (QA-DEV) revisará tu PR y podrá:
✅ Aprobar
Merge a pre-produccion
⚠️ Aprobar con observaciones
Merge con notas
❌ Rechazar
Corregir y volver a enviar

🤖 Cómo Usar IA para Llenar los Templates

💡 ¿Por qué usar IA?
  • Ahorra tiempo escribiendo documentación
  • Genera templates completos y profesionales
  • Ayuda a documentar correctamente
  • Reduce errores olvidados
  • Mejora la calidad del PR

📝 Ejemplo 2: Bug Fix con IA
Prompt para la IA:
"Tengo un bug: cuando un usuario intenta enviar facturas a México, el sistema falla con error 500. El error está en el servicio de facturación, específicamente en el método SendToMexico(). El problema es que no valida si el RFC es válido antes de enviar. Ayúdame a llenar el template BUG_FIX_SIMPLE.md"
Resultado con IA
## Task
- ID: #456
- Title: Corregir envío de facturas a México
- Type: Bug Fix

## Objetivo
Corregir error 500 al enviar facturas a México. El sistema fallaba porque no validaba el RFC antes de enviar.

## Cambios realizados
- Agregué validación de RFC en SendToMexico()
- Agregué mensaje de error claro cuando RFC es inválido
- Agregué logs para debugging

## Cómo probar
1. Ir a módulo de facturación
2. Seleccionar destino: México
3. Ingresar RFC inválido (ej: ABC123)
4. Verificar que muestra error "RFC inválido"
5. Ingresar RFC válido y verificar que envía correctamente
📝 Ejemplo 3: Refactor con IA
Prompt para la IA:
"Estoy refactorizando el módulo de inventario. Estoy moviendo todos los servicios de una sola carpeta a subcarpetas por dominio (Products/, Stock/, Transfers/). No cambié comportamiento, solo reestructuré. Ayúdame a llenar el template REFACTOR_SIMPLE.md"
Resultado con IA
## Task
- ID: #789
- Title: Reestructurar módulo de inventario por dominio
- Type: Refactor

## Objetivo
Reestructurar el módulo de inventario separando servicios por dominio para mejorar legibilidad y mantenibilidad.

## Cambios realizados
- Moví ProductService.cs a Products/ProductService.cs
- Moví StockService.cs a Stock/StockService.cs
- Moví TransferService.cs a Transfers/TransferService.cs
- Actualicé imports en archivos dependientes

## Cómo probar
1. Verificar que el código compila sin errores
2. Probar funcionalidad de productos (crear, editar, eliminar)
3. Probar funcionalidad de stock (consultar, ajustar)
4. Probar funcionalidad de transferencias (crear, aprobar)
💡 Tips para mejores resultados con IA
  • Sé específico: "El error ocurre cuando hago X, el mensaje es Y"
  • Incluye contexto: "Estoy trabajando en el módulo de facturación"
  • Menciona archivos: "El cambio está en Services/FacturacionService.cs"
  • Pide formato: "Dame el resultado en formato markdown"
  • Revisa y ajusta: La IA puede equivocarse, siempre revisa

🚨 Errores Comunes y Cómo Evitarlos

❌ Errores Comunes
  • ❌ Crear rama desde otra feature
  • ❌ Push directo a main
  • ❌ PR sin documentar
  • ❌ No hacer git pull antes
  • ❌ Usar template incorrecto
  • ❌ No incluir tests
✅ Cómo Hacerlo Bien
  • ✅ Siempre desde pre-produccion (o main para hotfix)
  • ✅ Siempre crear PR
  • ✅ Siempre documentar cambios
  • ✅ Siempre hacer git pull primero
  • ✅ Seleccionar template correcto
  • ✅ Incluir tests y evidencia
