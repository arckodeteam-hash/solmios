API de SolmiOS

Todo lo que ves en el panel y en la app móvil pasa por la misma API REST. Si tu hotel necesita conectar otra herramienta —un BI, un contador, un bot propio— estos son los cimientos.

01URL base y formato

Toda la API habla JSON sobre HTTPS:

https://hotel.zx89.site/api

Cada respuesta tiene la misma forma, pase bien o pase mal:

{
  "success": true,
  "data":    { ... },        // lo pedido, si salió bien
  "error":   null,           // { code, message } si falló
  "meta":    null            // paginación, cuando aplica
}

02Autenticación

Se inicia sesión con las credenciales de tu cuenta de SolmiOS y la API devuelve un token. Ese token viaja en el header de todas las llamadas siguientes:

Authorization: Bearer <token>

El token tiene vencimiento; cuando expira, la API responde 401 y se repite el login. Los permisos son los mismos que tiene tu usuario en el panel: un rol de recepción no puede llamar a endpoints que no ve en su pantalla.

03Ejemplos reales

Dos llamadas para probar en un minuto, con cualquier usuario del hotel:

Login

POST /api/auth/login
{ "email": "tu@hotel.com", "password": "••••••" }

→ data: { token, user: { id, name, email, role, hotelId, hotelName } }

Indicadores del día

GET /api/dashboard        (con header Bearer)

→ data: {
    ocupacion, totalRooms, checkins, checkouts,
    dirty, maintenance, huespedes, reservas,
    revenue, roomsByStatus, roomsByType, trends
  }

04Errores

Los códigos HTTP cuentan la historia: 400 datos inválidos, 401 token ausente o vencido, 403 sin permiso para ese módulo, 404 recurso inexistente, 409 conflicto de negocio (p. ej. una factura cobrada no se borra, se anula). El cuerpo siempre explica el motivo en error.message.

05Límites y buenas prácticas

  • La API tiene rate-limit por IP: haz lotes, no ráfagas. Si te pasas, recibes 429 con el tiempo de espera.
  • El estado del servicio, en vivo, está en la página de Estado del sistema (el check público es GET /api/health).
  • Para integraciones de canal (OTAs), lo correcto no es la API directa sino el channel manager integrado — evita pelearse con disponibilidad a mano.
  • ¿Necesitas un endpoint que no existe o un permiso específico para un integrador? Escríbenos desde Contacto con el caso de uso.
La API se versiona agregando, no rompiendo: los campos que existen hoy siguen existiendo. Si algún día un cambio es incompatible, se avisa con meses de anticipación a los integradores registrados.
