## Hallazgos

### HIGH

**H1. Crear mensajes automáticos es imposible (Mensajería → Envíos Auto)**
`POST /api/auto-messages` devuelve 400 SIEMPRE desde la UI. El frontend no envía `hotelId`
(`frontend/src/pages/auto-messages/index.vue:302` — `const data = { ...form.value }`), pero el
schema lo exige (`backend/src/modules/marketing/validators/schema.ts:5` — `hotelId: required`),
y el controller lo inyecta DESPUÉS de validar (`backend/src/modules/marketing/controller.ts:27`).
Repro API (dev): sin hotelId → `400 {"fields":{"hotelId":["hotelId is required"]}}`; con hotelId → 201.
Log dev: `POST /api/auto-messages ERROR ValidationError`. UI: modal cierra, toast genérico "Error"
(`auto-messages/index.vue:307` — `catch { toast.error('Error') }`), lista queda en 0.
Prod: mismo código deployado (commit `ec70d47`, fuera del diff sucio actual); 0 mensajes en prod es
consistente con "nadie pudo crear nunca". **Fix**: inyectar `hotelId` antes de `validateSchema` (o
quitar `required` del schema, ya que `hotelIdFor(req)` es la fuente autoritativa).

**H2. Crear plantillas WhatsApp es imposible (Mensajería → Plantillas WhatsApp)**
Mismo patrón exacto: `whatsapp-templates/index.vue:320` no envía hotelId;
`CreateTemplateSchema` (schema.ts:21) lo exige; controller inyecta después (controller.ts:50-52).
Repro API dev: `POST /api/whatsapp-templates` sin hotelId → 400 `hotelId is required`.
Toast: "Validation error" (inglés, no dice el campo). Prod: 0 plantillas.

### MEDIUM

**M1. SearchSelect no reabre tras scroll y corrompe el valor tipeado (Hotel: País/Moneda/Zona horaria)**
Repro real (dev, eventos reales de Playwright): click en País → dropdown abre (196 items) →
scroll de página → `closeOnScroll` cierra el dropdown pero el input CONSERVA el foco → click
de nuevo → **no reabre** (solo está bound a `@focus`, que no refire sobre un elemento ya enfocado;
`frontend/src/components/ui/SearchSelect.vue` template) → tipeo "Argentina" → el valor queda
`"República DominicanaArgentina"` (el label cerrado es el `value` del input) → lista "Sin resultados".
Recuperable solo haciendo blur consciente en otro campo. Afecta los 3 selectores del form principal
del hotel. Fix de 1 línea: `@mousedown`/`@click` en el input que llame `openDropdown()` (idempotente).

**M2. SearchSelect inaccesible por teclado (a11y)** — las opciones solo se eligen con mouse
(`li @mousedown.prevent="choose"`), el `onKeydown` solo maneja Escape; el dropdown teleported no
expone roles `listbox/option`. Un usuario de teclado puede filtrar pero no seleccionar.
`SearchSelect.vue:110-116` y template.

**M3. Auditoría sin filtros ni export** — con 218 eventos (prod) y 1.759 (dev) solo hay paginación
(20/pág, funciona: "21–40 de 1759" verificado). Sin búsqueda por texto (limitación backend documentada
en `frontend/src/pages/auditoria/index.vue:102-103` — RepositoryAdapter sin LIKE), sin filtro por
acción/usuario/fecha, sin export. Columna Detalle = JSON crudo truncado (`{\"status\":\"pending\"...}`).

**M4. Tarifas: rangos solapados sin validación ni warning** — guardé Baja con fin 2026-06-15
quedando solapada con Media (inicio 2026-06-01): sin aviso ni bloqueo
(`frontend/src/pages/tarifas/index.vue` no tiene validación de overlap). Qué temporada gana para
esas fechas queda indefinido para el usuario. Verificado en DB: `seasons` baja endDate=2026-06-15.

**M5. Amenities: persistencia asimétrica** — la amenity custom se auto-guarda al agregar
(`settings/index.vue:1281` → `configuration.custom_amenities`, verificado en DB), pero la
SELECCIÓN de checkboxes solo persiste con el "Guardar" global del header (línea 1465,
`saveAmenitiesHotel`). Al navegar away el `beforeunload` avisa (verificado: disparó), pero dos
rutas de persistencia en la misma tab es una trampa: el usuario ve "agregada" y cree que quedó.

**M6. Dispositivos: contadores en 0 con sesión activa, inconsistente con Push** — prod mostró
"Dispositivos Registrados 0 · Sesiones Activas 0 · Usuarios Conectados 0" mientras había una
sesión web admin activa (la mía); a la vez Mensajería→Push lista 6 dispositivos Android del hotel.
La página lee la tabla `devices` (`devices/index.vue:289`, `OperationsService.dispositivos`), no
sesiones reales: el copy promete "Conectadas en este momento" y muestra un catálogo de registros.

**M7. Email automático con subject en inglés** — Cola de Emails (dev): "Your booking at Hotel
Boutique Palma — no-show" para un hotel configurado en español. Comunicación guest-facing en
idioma incorrecto (plantilla default del no-show).

**M8. Prod corre un build más viejo que el código** — el empty state de la matriz de tarifas en
prod dice "Creá habitaciones con tipo definido..." sin CTA, mientras el código actual tiene
"Crear habitaciones" como router-link condicionado (`tarifas/index.vue:144-150`). No es bug del
código: falta deploy. Caveat para cualquier comparación prod vs repo esta semana.

## Resumen ejecutivo

**Ranking peor → mejor**: Mensajería 58 · Dispositivos 72 · Auditoría 72 · Tarifas 80 ·
Condiciones 82 · Hotel 84 · Amenities 84 · Descripción 85 · Ubicación 85 · Integraciones 86 ·
Promociones 90 · Emergencias 90 · Cerraduras 90 · Pasarelas 92 · RRHH 93.

La sección está en buen estado general (guardado, validación, estados, responsive y toasts muy
por encima de la media del panel). El problema grave está concentrado: **Mensajería no permite
crear nada** por un bug de validación backend (H1/H2, mismo fix de fondo para ambos), y los tres
selectores del form principal del hotel tienen una trampa de interacción (M1).

**Top 5 mejoras por impacto**:
1. **Fix hotelId en marketing** (inyectar antes de validar o sacarlo del schema requerido) —
   desbloquea las 2 acciones HIGH; cambio de ~3 líneas en `controller.ts`.
2. **SearchSelect**: reabrir con click (`@mousedown` → `openDropdown`) + selección por teclado
   (Enter/flechas) + roles `listbox/option` — repara M1 y M2 en el componente que usan
   país/moneda/TZ (y el resto del panel que lo importa).
3. **Auditoría útil**: filtro por acción/usuario/rango de fechas + export CSV + detalle
   expandible con JSON formateado (hoy 1.759 eventos en dev sin forma de encontrar nada).
4. **Unificar persistencia de Amenities**: auto-save de la selección (o botón Guardar en la card),
   eliminando la doble ruta que hoy pierde la selección al navegar.
5. **Dispositivos**: mostrar sesiones reales (o renombrar el copy a "dispositivos registrados") y
   reconciliar con Push-tokens (6 vs 0 según la pantalla).

**Notas de entorno**: la DB de dev usada fue una copia (`/tmp/qa-config.db`) — los datos QA escritos
no afectan la DB de la otra sesión. El vite config temporal (5174→3002) se eliminó; quedó en el
árbol solo su eliminación (fue commiteado por error en `53a367f`). No se tocó código: typecheck N/A.
